# 主流程自测指引

> 用途：让你**自己动手**把工程审计平台的两条主链路完整跑一遍 ——
> **甲. 审计主流程**（项目 → 资料 → 核对 → 台账 → 问答 → 导出）
> **乙. 清标分析**（控制价 + N 家投标 → 逐项比对 → 清标报告）
>
> 本指引中的按钮文案、字段名、资料清单均与当前代码一致，可照着点。
> 整理时间：2026-09-23

---

## 0. 起跑前

### 0.1 启动服务

```bash
cd server
npm install          # 首次
npm start            # 默认监听 3003
```

- 应用入口：<http://localhost:3003/>
- 默认管理员：`admin` / `123456`
- 确认在跑：浏览器打开入口能跳到登录页即正常。

### 0.2 先看一眼「模型配置」

侧边栏「🤖 模型配置」→ 进入后**逐个点「测试连通性」**。

- 清标分析、智能问答都走这条**模型链**（从上往下依次尝试，前一个失败才试下一个）。
- 若主模型不可用，会自动降级到下一个 —— 报告还能出，但耗时更长、质量可能下降。**自测前先确认至少一个模型是通的**，否则你会误以为是功能坏了。
- 眼睛（OCR 解析）固定用 PaddleOCR-VL，**与本页配置无关**；确认 OCR 服务（默认 8080）也是活的。

### 0.3 两份资料在哪

| 资料 | 位置 | 用途 |
|------|------|------|
| **审计资料包（推荐）** | `docs/audit-samples/` | **甲链路首选**——两个**内部自洽**的完整项目（A 房建装修·规范 / B 市政道路·埋考点），清单与结算同项目同编码，勾稽能跑出真实结果 |
| 审计负样本 | `docs/samples/06-projects-001/` | 甲链路**负样本**——清单（安徽郎溪）与结算（广东东莞）**分属不同项目**，用来验证系统不会硬凑结论 |
| 审计扩展素材 | `docs/samples/扩展素材（可选）/` | 加压、跨项目对比、大文件 OCR |
| 清标资料包 | `docs/bid-clearing-samples/` | 乙链路（5 组，见 §2.2） |

> 资料包**未纳入版本库**，是本地文件；各目录内的 `README.md` 写明了每份文件的真实来源与测试点，建议先扫一眼。

### 0.4 跑之前先给资料包做个体检（可选，推荐）

**审计资料包**（走系统真实的 Excel 解析器 + OCR 链路）：

```bash
cd server
node scripts/verify-audit-packs.mjs          # 校验清单 xlsx 的 sheet 名与六列识别（秒级）
node scripts/verify-audit-packs.mjs --ocr    # 追加：把结算 PDF 送真实 OCR，并核对两侧编码对齐
node scripts/verify-audit-packs.mjs --ocr --pack=B   # 只跑某一个项目
```

会输出清单 sheet 是否命中、编码/名称/单位/工程量/单价/合价六列是否都能识别、提取到的项数与合价合计；OCR 模式下还会打印结算 PDF 表格的 `anchor_label` 与两侧编码的 match / diff 预期。

**清标资料包**：

```bash
node scripts/verify-clearing-pack.mjs                     # 校验全部组
node scripts/verify-clearing-pack.mjs "第5组-吴江七都（装修改造）"   # 只校验某一组
```

**当前基线：第 4 组 17/17、第 5 组 18/18 通过**；第 1/2/3 组会显示⏭跳过并说明原因（脚本只解析 xlsx，且只适配「分部分项 + 汇总」这一种清单表结构），需在页面上手工验证。

## 甲 · 审计主流程

### A1 新建项目

1. 侧边栏「📁 审计项目」；
2. 点右上角「**新建项目**」，填：

   | 字段 | 说明 |
   |------|------|
   | 项目名称 | 建议用脱敏代称，如 `自测-某改造项目` |
   | 项目编号 | 自拟，如 `TEST-2026-001` |
   | 审计类型 | 按需选（结算审计 / 预算审计 …） |
   | 审计/工程期间 | 如 `2025.03-2026.08` |
   | 项目说明 | 可留空 |

3. 保存后，卡片出现在列表里（搜索框 placeholder 是「搜索项目名称 / 编号」，可用来验证检索）；
4. **点卡片进入项目** —— 后续四步都在项目内。

### A2 资料舱：上传整个项目资料

**推荐用 `docs/audit-samples/` 里的两个自洽项目**（清单与结算同项目同编码，勾稽跑得出真实结果）：

| 项目目录 | 上传哪些文件 | 资料数 |
|---|---|---|
| `项目A-房建装修（资料规范）/` | `01`～`06` 共 6 份 | 覆盖全部 6 类归类 |
| `项目B-市政道路（埋考点）/` | `01`～`07` 共 7 份 | 含 2 张连号发票 |

进入「📄 资料舱」，把某个项目目录下的文件**一次性全选拖进去**（`原始下载/` 子目录不用传）。系统会自动排队解析并归类。以项目 A 为例：

| # | 文件 | 期望归类 |
|---|------|----------|
| 01 | 郎溪县公安局"基础管控中心"改造项目-工程量清单.xlsx | 工程量清单 |
| 02 | 郎溪县公安局"基础管控中心"改造项目-结算审核书.pdf | 结算/审核 |
| 03 | 建设工程施工合同（GF-2017-0201）.docx | 合同/协议 |
| 04 | 现场签证单.pdf | 变更签证 |
| 05 | 增值税专用发票.png | 发票 |
| 06 | 施工现场照片.png | 现场照片 |

**这里要看的：**

- 6 份资料是否被自动分到 6 个不同类别（这是「自动归类」能力的关键验证点）；
- 状态流转：`排队 → 解析中 → 已解析`；
- 结算 PDF 走逐页 OCR，比 Excel 慢，会明显看到「解析中」停留较久，属正常；
- 若有失败项，页面上有「**重试全部失败项**」和「**刷新**」可点。

> 支持格式：`.pdf / .docx / .xlsx / .xls / .png / .jpg / .jpeg / .webp`

> **负样本（可选，对照用）**：`docs/samples/06-projects-001/` 里的 6 份是另一套资料，其中清单（安徽郎溪）与结算书（广东东莞）**分属不同项目**——这是**故意保留的负样本**，用来验证系统在数据不匹配时**不会硬凑结论**。它的勾稽应表现为「无法确认」，而不是算出核减。详见 §A4。

### A3 看一眼解析结果与证据锚点

在资料列表里点开任意一份已解析资料，检查（以项目 A 为例）：

- **01 清单.xlsx** → 是否读到 34 条清单项，分部分项工程费合计 **190,029.56**；
- **03 合同.docx** → 是否抽到签约合同价 **208,473.16**、预付款 20%、质保金 3%、缺陷责任期 24 个月；
- **02 结算审核书.pdf** → 是否还原出 **送审 214,000.00 → 审定 208,153.95 → 核减 5,846.05（核减率 2.73%）**，且每行能回填原书页码；
- **04 签证单.pdf** → 三方单位（建设 / 监理 / 施工）、工程量、以及**印章**是否识别到；
- **05 发票.png** → 发票代码 `3400201130`、号码 `02841937`、价税合计 `104,000.00`、税率 9%。

> 「证据锚点」= 结论能点回到**具体文件 + 页码 / sheet / 单元格**，这是本平台的卖点，务必点几下确认能跳转。

### A4 核对程序

进入「✅ 核对程序」，跑两个程序（**务必用 A/B 两个自洽项目来跑**）：

| 按钮 | 用到的资料 | 期望 |
|------|-----------|------|
| ▶ 清单↔结算勾稽 | 清单.xlsx + 结算.pdf（**同一项目**） | ✅ 应算出真实结果：**项目A 34 项中 32 匹配 / 2 差异**；**项目B 30 个编码中 23 匹配 / 7 差异**（含漏项与多计）。差异的编码、金额、差额都要能对上 `docs/audit-samples/README.md` 里的预期表 |
| ▶ 三方签章核对 | 签证单 / 合同 / 结算签署页 | **项目A** 三方签章齐全（全匹配）；**项目B** 签证单缺监理单位签章 → 应报出差异 |

> **负样本对照**：拿 `docs/samples/06-projects-001/` 跑勾稽，正确表现是**「无法确认」三态**（清单与结算分属不同项目）——如果它硬是算出核增核减，那才是 bug。

### A5 疑点台账

进入「⚠️ 疑点台账」：

1. 点「**↻ 重新扫描**」，等扫描完成；
2. 核对命中的疑点类型：

   | 疑点类型 | 项目A 预期 | 项目B 预期 |
   |---|---|---|
   | 金额凑整 `round_amount` | 有（低危，真实数据天然特征，如更衣柜 3,000、工位 8,000） | 有（新增项 60,000 整万·中危；措施项 8,000 整千） |
   | 三无签证 `no_seal` | 无 | **有**（签证单缺编号、日期） |
   | 连号发票 `invoice_serial` | 无（仅 1 张） | **有**（代码 `4600202350`，号码 `05123406`/`05123407` 连续） |
   | 清单↔结算差异 `check` | 2 条 | **7 条** |

3. 点「**⬇ 导出 Excel 台账**」和「**⬇ 导出 Word 发现清单**」，打开产物确认：
   - Excel 台账应含核对明细 + 疑点清单，且**含核增核减汇总公式**；
   - Word 是按发现条目成文的可交付文档。

### A6 智能问答（含溯源）

进入「💬 智能问答」，依次问这几类，**重点看它会不会瞎编**：

**① 可正问（资料里有答案）**
- `本项目分部分项工程费是多少？结算的送审造价和审定造价分别是多少？`（项目A）
- `合同里的质量保证金比例和缺陷责任期是多少？` → 3% / 24 个月
- `结算审核书的核减额和核减率是多少？` → 5,846.05 / 2.73%
- `签证单上有哪几方签章？是否齐全？`

**② 溯源问（应有页码/单元格）**
- `核减金额的依据在第几页？`
- `发票的价税合计是多少？在哪个位置？`

**③ 反向校验差（项目B 专用）**
- `挖一般土方的工程量在清单和结算中分别是多少？` → 131 / 158
- `结算中是否有多出来的清单项？金额多少？` → `040501001003` / 60,000.00
- `结算造价与合同价相比超出多少？` → +68,198.30
- `两张发票的号码是否连续？` → `05123406` / `05123407` 连号
- `现场签证单的手续是否完备？` → 缺编号、日期、监理签章

**④ 反问（资料里没有 → 应回答"未在已提供资料中发现"）**
- `有没有监理合同？`
- `有没有材料进场检验报告？`

> **判定标准：** ④ 类问题如果它开始编造具体的监理单位名称或合同编号，那就是**幻觉**，是 bug，值得记下来。

## 乙 · 清标分析

清标是**独立功能**，不占审计项目（任务的 `project_id` 可为空），可以跳过甲链路单独跑。

### B1 先搞懂两种形态

| 形态 | 上传什么 | 系统能做什么 |
|------|----------|--------------|
| **清单级** | 控制价 + 投标文件里**带分部分项清单**（有项目编码 / 名称 / 工程量 / 综合单价） | 能**逐项比对**综合单价，跑满全部 12 类核验（含算术性错误、不平衡报价、漏报、零报价） |
| **总价级** | 只有投标总价与费用构成（措施费、暂列金额、规费税金） | 只能比对**报价离散度与费用构成**，报告里会明说"未提供分部分项清单，无法逐笔复核"（这本身是反幻觉的加分表现） |

> **容量上限（重要）**：控制价单份 **4 万字符**、投标方单份 **3 万字符**、合计 **16 万字符**，超出部分会被截断。
> 这就是为什么第 4 组是「**260 项节选**」而不是整份 814 项清单 —— 整份投喂会导致控制价与各家报价在**不同位置**被截断，从而比对出**假漏项**。

### B2 建任务并上传

1. 侧边栏「🧹 清标分析」→ 点「**+ 新建清标任务**」命名（如 `自测-第4组`）；
2. 进入任务详情页，有两大区块：
   - **📋 资料配置**
     - **🏷️ 招标控制价** → 点击上传**1 份**；
     - **🏢 投标方**（提示"最多10家，点击方块上传报价"）→ 每家一个方块，点方块上传该家的报价文件，并填写**投标单位名称**；
   - **🧾 清标报告** → 「▶ 开始清标分析」「⬇ 下载报告」。

   > 页面顶部还有「✏ 重命名」「删除任务」「‹ 返回列表」。

3. 每家可挂**多份**文件；上传后等**全部解析完成**（方块/状态线会显示解析进度）。

### B3 开始分析

等页面提示**「可分析」**后，点「**▶ 开始清标分析**」；状态会变「分析中…」，**每 3 秒自动刷新**。完成后报告渲染在下方，点「**⬇ 下载报告**」可导出 Markdown。

报告按 **12 类核验项**分章：

一、算术性错误 · 二、清单编码与项目名称规范性 · 三、安全文明施工费费率 · 四、暂列金额一致性 · 五、主要材料及设备价格 · 六、非实质性响应 · 七、不平衡报价 · 八、其他问题及建议 · 九、项目名称一致性 · 十、废标红线 · 十一、非标红线专区 · 十二、报价规律性分析

末尾附「**清标结论汇总**」表（各投标方问题项数 / 风险等级 / 总体建议）。

### B4 5 组资料怎么选（建议顺序）

| 顺序 | 组 | 形态 | 构成 | 特点与考点 |

## 丁 · 常见问题

| 现象 | 排查方向 |
|------|----------|
| 清标分析一直「分析中…」不结束 | ① 模型链是否至少一个可用；② 输入是否超容量上限（控制价 4 万 / 单份 3 万 / 合计 16 万字符），超了会被截断甚至报错 |
| 点「开始清标分析」按钮用不了 | 是否有资料仍在解析中；页面提示「可分析」后才可点 |
| 报告里出现"假漏项" | 大概率是**清单被截断**导致：用**第 4 组的节选版**，不要自己塞整份 814 项清单 |
| 勾稽结果全是「无法确认」 | 清单与结算**不是同一个项目**。换用 `docs/audit-samples/` 的自洽项目；06 样本是故意留的负样本 |
| 勾稽差异项全空 / 一项都没 | 检查清单 xlsx 的 sheet 名是否含「分部分项」；结算 PDF 中表格上方是否有**居中的**「分部分项工程量清单与计价表」标题 |
| 扫描件解析特别慢 | 纯扫描 PDF 走逐页 OCR/VLM，124 页或 36 页都会慢；属正常，不是卡死 |
| 导出 Excel/Word 没反应 | 确认浏览器未拦截下载；再看后端日志有无报错 |
| 登录后接口报 `Not allowed by CORS` | 见主 README「常见问题：登录报 Not allowed by CORS」章节 |

## 附 · 建议的自测顺序（一口气版）

```
1) 启动服务 → 模型配置测连通
2) 甲链路（用 audit-samples 的自洽项目）：
   项目A：新建项目 → 传 6 份资料 → 看锚点
        → 清单↔结算勾稽（预期 32 匹配 / 2 差异）→ 三方签章核对
        → 疑点台账（预期以低危凑整为主）→ 导出
   项目B：再建一个 → 传 7 份资料
        → 勾稽（预期 23 匹配 / 7 差异）→ 三方签章（缺监理）
        → 疑点台账（三无签证 + 连号发票 + 凑整）→ 导出
        → 智能问答：正问 + 溯源问 + 反向校验差问 + 反问（验幻觉）
3) 负样本对照（可选）：用 docs/samples/06-projects-001/ 跑勾稽
        → 正确表现是「无法确认」而不是硬凑核减
4) 乙链路：清标 → 第 4 组（全 Excel、秒级、考点最密）
        → 对照 §B4 的"埋雷表"逐条验报告
5) 有余力：清标第 2 组（最小组）→ 第 1 组 → 第 3 组 → 第 5 组（含 124 页扫描件压测）
```

跑完这一轮，两条主链路的每一环（上传 → 解析 → 锚点 → 核对 → 台账 → 问答 → 导出 / 清标报告）就都被覆盖到了。
